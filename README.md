# budgetgate-action-test

End-to-end test repository for [soroban-budget-action](https://github.com/BudgetGate/soroban-budget-action). Not a product; nothing here is meant for reuse.

`contracts/counter/` is the counter contract from [soroban-budget-core `testdata/counter/`](https://github.com/BudgetGate/soroban-budget-core/tree/main/testdata/counter) (v1 on `main`). `contracts/vault/` has a constructor (an admin address and a limit) and a `deposit` that takes arguments and needs the depositor's authorization; it is measured twice, from the transaction's source and from a second funded account (`deposit_alice`, which adds that account's signature check and nonce). `contracts/greeter/` takes text and a list, so its fixture calls pass quoted arguments with spaces (`'Budget Gate'`, `'[1, 2, 3]'`). `contracts/relay/` takes the counter's ID in its constructor and calls the counter's `bump`, so its cost includes the counter's. Every run builds the workspace with the Rust version pinned in `rust-toolchain.toml` (crates and compiled dependencies cached on `rust-toolchain.toml` and `Cargo.lock`), deploys the three contracts to testnet with a throwaway friendbot-funded key, and writes `budget/fixture.json` with one call per contract against those deployments (`budget/build-fixture.sh`, with `CONTRACTS` and `CALLS` set), then runs the Action. A pull request is therefore measured on its own code: changing `contracts/counter/src/lib.rs` to the v2 code (a known cost rise) shows a regression. Testnet resets do not affect it, since nothing outlives a run.
